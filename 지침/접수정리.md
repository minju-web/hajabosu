# 접수 정리 지침

접수 원문 1건을 읽고 하자대장에 들어갈 항목을 **JSON 하나**로 출력한다.
기준: `data/업무설명_하자보수.md` (충돌하면 그 문서가 우선)

## 역할 범위

AI는 **의미 해석이 필요한 항목만** 채운다. 아래는 코드가 하므로 출력하지 않는다.

| AI가 출력 | 코드가 처리 (출력 금지) |
|---|---|
| 접수일, 위치, 공종, 하자내용, 긴급도 | 접수번호, 조치기한, 공사번호, 시공업체, 준공일, 보증만료일, 보증판정, 책임구분, 상태, 비고 |

날짜 계산, 공사정보 조회, 보증 판정은 하지 않는다.

## 입력

- 원문 파일 1개 (현장 메모, 메일, 메신저 중 하나, 형식이 제각각)
- 원문 파일명 (예: `01_20261102_B1푸드코트_누수.txt`)

## 출력 형식

설명, 인사말, 코드 펜스 없이 **JSON 객체 하나만** 출력한다. 원문 1건당 1개.

```json
{
  "원문파일": "01_20261102_B1푸드코트_누수.txt",
  "접수일": "2026-11-02",
  "위치": "B1 푸드코트",
  "공종": "방수",
  "하자내용": "중앙 통로 3번 매장 앞 천장 누수, 마감재 얼룩",
  "긴급도": "긴급",
  "긴급도_근거": "천장에서 물이 떨어짐(누수)"
}
```

| 키 | 형식 | 규칙 |
|---|---|---|
| 원문파일 | 문자열 | 입력받은 파일명 그대로 |
| 접수일 | `YYYY-MM-DD` | 아래 "접수일" 참고 |
| 위치 | `층 구역` | 아래 "위치" 참고 |
| 공종 | 문자열 | 아래 "공종" 참고 |
| 하자내용 | 문자열 | 40자 이내 요약 |
| 긴급도 | `긴급` / `높음` / `보통` | 아래 "긴급도" 참고 |
| 긴급도_근거 | 문자열 | 긴급도를 정한 원문 단서 한 줄. 사람이 검토할 때 쓴다 |

## 항목별 규칙

### 접수일
- 원문에 적힌 날짜를 쓴다. (메모 머리말, 메일·메신저의 날짜 줄)
- 원문에 날짜가 없으면 파일명 앞부분의 날짜(`YYYYMMDD`)를 쓴다.
- 시각(14:20 등)은 버린다.

### 위치
- 형식은 `층 구역`. 예: `B1 푸드코트`, `2F 화장실`, `3F 패션관`, `5F 레스토랑가`, `1F 정문`
- 층은 `B2`, `B1`, `1F`, `2F`처럼 쓴다. (`3층` → `3F`, `지하1층` → `B1`)
- 매장 번호, 기둥 번호, 남녀 구분, 세면대 앞 같은 **세부 위치는 위치에 넣지 않고 하자내용에 적는다.**
- 구역 이름은 공사정보의 위치 표기와 같게 쓴다. (예: 원문 "정문" → `1F 정문`) 코드가 그 문자열로 공사를 찾기 때문이다.
- 원문으로 층이나 구역을 알 수 없으면 추측하지 말고 알 수 있는 부분만 쓴다.

### 공종
허용 값은 7개뿐이다: `방수`, `타일`, `전기`, `설비`, `기계`, `도장`, `바닥재`

| 공종 | 원문 단서 |
|---|---|
| 방수 | 누수, 천장에서 물 떨어짐 |
| 타일 | 타일 들뜸·깨짐·줄눈, 바닥 기울기 |
| 전기 | 조명, 콘센트, 분전반, 누전, 전원 |
| 설비 | 배관, 배수 막힘, 급수, 수전 |
| 기계 | 자동문, 셔터, 주차 차단기, 엘리베이터, 에스컬레이터 |
| 도장 | 페인트 벗겨짐·변색 |
| 바닥재 | 에폭시, 바닥 코팅, 장판 |

- 원문만으로 하나로 정할 수 없으면 후보를 `설비/타일`처럼 `/`로 함께 적는다. 담당자가 현장을 보고 정한다.
- 후보 병기는 단서가 실제로 갈릴 때만 쓴다. 단서가 분명하면 하나만 쓴다.
- 7개 밖의 공종 이름을 만들지 않는다.

### 하자내용
- **40자 이내**로 요약한다. (공백 포함)
- 포함: 세부 위치(매장·기둥·남녀·세면대 앞 등), 증상, 필요하면 규모
- 제외: 순찰자, 인사말, 사진 장수, 사과·요청 표현
- 원문에 없는 원인이나 사실을 지어내지 않는다. 원인이 불명확하면 불명확하다고 쓴다.

### 긴급도

| 긴급도 | 기준 |
|---|---|
| 긴급 | 누수, 전기 이상, 고객 안전 위험(넘어짐·미끄러짐·추락) |
| 높음 | 고객 출입·영업 지장(출입문·자동문·주차 출구 이상, 고객 시설 사용 불가, 고객 민원) |
| 보통 | 그 외(미관, 운영 지장 없음) |

- 여러 기준에 걸리면 **가장 높은 긴급도**를 쓴다.
- **고객은 이용 고객이다.** 입점 매장(테넌트)의 문의는 고객 민원으로 보지 않는다.
- "넘어질 뻔함", "미끄러짐 우려"는 고객 안전 위험으로 본다.
- 판단이 경계에 있으면 `긴급도_근거`에 그 사실을 적는다. 사람이 검토한다.

## 하지 말 것

- 접수번호, 조치기한, 공사번호, 시공업체, 보증 관련 항목을 출력하지 않는다.
- 위 키 외에 다른 키를 추가하지 않는다.
- JSON 앞뒤에 설명 문장을 붙이지 않는다.
- 원문에 없는 내용을 추측해서 채우지 않는다.

## 예시 2

입력 파일명: `04_20261105_2F화장실_물고임.txt`

원문 요지: 2층 여자화장실 세면대 앞 바닥에 물이 고임. 배수 불량인지 바닥 기울기 문제인지 모름. 청소 후 30분이면 다시 고임. 미끄럼 주의 표지판 세움.

```json
{
  "원문파일": "04_20261105_2F화장실_물고임.txt",
  "접수일": "2026-11-05",
  "위치": "2F 화장실",
  "공종": "설비/타일",
  "하자내용": "여자화장실 세면대 앞 바닥 물고임, 배수·기울기 원인 불명",
  "긴급도": "긴급",
  "긴급도_근거": "미끄러짐 우려로 표지판 설치(고객 안전 위험)"
}
```
